# 图标生成 · 设计与工程规范

生成风格一致、可稳定切割的图标集的通用做法与规则。只写通用原则，不含具体项目案例。

## 一、工具约束

- 常见的 gpt-image 路径（Codex / OpenAI Images）只接受 `prompt` 文本、不能喂参考图 → 风格一致靠统一提示词；画图工具按能力自适应选择（见 `references/image-providers.md`），稳定切割靠切图脚本。
- 输出是位图 PNG（约 1254×1254 方图），不是矢量；尺寸 / 透明 / 张数不可直接指定，全在 prompt 里描述。
- 位图 hold 不住"系统级"图标（见第五节）。

## 二、构图与切图

- 一张 4×4 sheet 一次生成 16 个：同一次生成里风格天然统一，也省成本。图标多用 4×4；追求切割稳定用 3×3（9 个，格子更大、间距更足、更好切）。
- 提示词要求纯灰 `#808080`、无文字、无网格线、图标间留足间距、不投影到背景；`#808080` 是生成目标，不是供应商实际像素值的保证。
- 切图脚本从整张图的外边缘和格间空隙统计主导背景色、噪声与采样一致性，避免仅取四角误采到图标 / 瓷砖。背景不可靠时自动尝试 rembg，同时保留色彩去背候选，并将每格标记为待复核；不要求用户另选安装方案。rembg 也会误删叶片、手部等主体细节，不是可靠性保证。
- 按网格分格并略微外扩（约 6%）兜住偏移，同时保留原格子边界，最后一行 / 列包含余下像素。
- 扁平硬边使用 `floodfill`：删除与实测背景紧密匹配的边界连通区域；封闭区域仅对近乎精确匹配的颜色透明化，并排除与外部连通的采样噪声区域，避免绕过更小的外部容差。接近灰色的主体不再按宽阈值整片删除。窄边缘有可靠前景参考时估算部分透明度并去除 RGB 中混入的背景色。
- 根据实际边缘选择方法，风格 JSON 的 `cutout` 仅为起点。卡通的粗描边、平涂和内部阴影本身不要求 rembg；灰底可分离的硬边优先 `floodfill`。软边或难以分离的轮廓可尝试 `rembg`：保留模型透明度，仅在颜色与透明度一致、附近存在可靠前景时修正边缘背景污染。没有可靠依据的边缘保留并交给 QA，不强行反推。
- `--thresh` 是边缘前景对比度与 QA 的颜色相似度参数，不再表示“这个色差以内全部删除”。默认外部去背容差来自采样噪声；`--background-tolerance` 可独立覆盖，仅影响与裁切边界连通的区域，不放宽封闭区域删除条件。由 agent 对照原稿逐格调整，不把 32 或其他个案值设为通用默认。封闭残底通过 `--repairs` 指定种子与局部矩形修整，详见 [切图修整](cutout-repair.md)。
- 连通域清理使用八邻域且保留低透明度边缘；本格内的小点缀、动作线、独立部件均保留。只清除完全位于外扩区，或大部分位于格外且被裁切边缘截断的部件。无法明确归属的跨界部件保留并提示检查。
- 优先阅读 `out/qa/summary.md`，`report.json` 为精简概览，全部区域保存在 `details/NN.json`：记录实测背景、采样可信度、各格模式、外部容差、局部修整及删除像素数、清理前后部件数，并提示疑似残灰 / 灰色主体、封闭透明孔、与原格相比前景颜色存在但抠图后几乎透明的局部区域、清理删掉的内容和触及格子边界的前景。局部缺失检测逐像素对照原图与抠图 alpha，因此相连部件也会提示；低对比窄边界差异归为 `edge_ambiguity` 信息提示，仍可能是细节损失，不能自动认定为噪声；强色差细小部件继续报缺失。主动局部修整单独记录为 `repaired_background`，不对同一修整掩膜重复报透明孔和缺失；选区外异常照常检测。每类区域提示包含像素数、区域总数和按面积排序的至多 3 个坐标示例；逐格明细保留所有区域，坐标相对该格的外扩裁切区域。背景不可信时，不运行基于背景色的缺失判断，但每格仍添加 `uncertain_background` 提示。rembg 与色彩候选不一致时添加 `candidate_disagreement` 提示，不能据此直接认定哪种结果正确。
- 默认生成六张编号预览：`source.png` 原格、`cutout.png` 抠图后、`cleaned.png` 清理后，以及最终 PNG 在洋红、白、深色底上的 `magenta.png` / `light.png` / `dark.png`。前三张保留同一格子的构图，方便定位哪一步丢失部件；最终预览对应裁边、居中及缩放后的交付图。使用 rembg 时额外保存 `colour-candidate.png` 对照预览和 `colour-candidates/NN.png` 原裁切尺寸候选；由 agent 比较原稿、模型结果与候选，必要时逐格切换模式后重新切图。
- 检测与验收分开记录：`error` / `review` / `info` 是自动提示级别；`pending` / `accepted` / `needs_fix` / `stale` 是视觉验收状态。Agent 对照原稿和三种底色后填写带图像指纹的验收文件，记录正常镂空、图案、噪声、修整或返修结论；重跑时原稿、参数、处理代码或输出改变，旧结论失效。无报警也不能自动验收，空图不能接受。格式见 [切图修整](cutout-repair.md)。
- 自动 QA 不代替逐图验收：正常镂空和灰色细节也可能被提示；与背景同色的实体和真实镂空无法仅靠颜色可靠区分。局部缺失检测只覆盖与背景有足够色差的区域，无法判断颜色近似背景或抠图 alpha 仍大于 32 的语义细节是否丢失。对照原格和设计意图处理疑点，不自动填满所有孔，也不因没有自动提示就直接验收通过。

## 三、一致性

- 机制：统一提示词。
- 调色板必须写死 hex，否则彩色风格会漂色；低饱和品牌色尤其会被拉艳。
- 可选：锚点法——新 sheet 里掺入已定稿图标，把风格拽回来。

## 四、风格规则

- 视觉重量层级（通用，最重要）：图标的"定义元素"（线性风格的线、面性风格的实心轮廓）必须始终是视觉最重的；点缀 / 第二色 / 细节的重量要压在它之下。视觉重量 ≈ 与底色的明度反差 × 面积 × 饱和度——线越细，点缀就得越浅越小。给细线配又深又大的实填会重量倒挂：线沦为框、深块抢焦点，整套就不像那个风格了。点缀优先用比线更浅的淡色 / 半透明、小到中面积；可用柔和渐变或材质增加"库级"质感，渐变也让点缀更轻。
- Duotone 双色：两色必须有反差（一深一浅拉开明度，或色相明显不同）；相近的低饱和两色会糊成一团、层次全丢。第二色语义化只点一个关键部件，不是每块形状随便刷两色。
- Solid 面性：实心是大色块，铺满一屏显脏。内容密集 / 编辑调性 UI 默认用 line 或 line + 极小点缀；solid 只用于小而稀疏的位置（tab bar、单个强调）。
- 面性单色需在 prompt 写死 hex，避免自作主张上多色。
- 柔和投影：prompt 写 no drop shadow 只减轻不根治；按实际轮廓比较去背结果，不因“卡通”或“3D”名称直接固定 rembg。

## 五、"设计感"

核心：给通用图标染品牌色 ≠ 品牌图标系统。缺设计感的根因：

1. 隐喻太通用直白（人+闪光=创作者、画框=作品、领奖台=排行榜）——没有品牌自己的视角 / 母题，换个色就是别家的。
2. 没有统一构造系统——图标系统是一套构造规则（同网格、同线宽、同圆角、同收笔、同"繁简预算"），一套图标共享同一副骨架。位图逐格徒手画会飘，读作"一堆相似但不成体系"。
3. 繁简不一致——抽象程度要统一。
4. 太写实不做减法——好图标把一个意思减到只剩本质。
5. 缺品牌母题 signature——一个反复出现的记号（呼应品牌圆角 / 字体 / 容器形），让人一眼认出是谁的。

补设计感：spec 先定构造系统（网格 + 线宽 + 圆角 + 收笔 + 繁简预算），而非只写"线性 + 某色"；定一个品牌母题让它复现；做减法；第二色语义化。真要成系统：位图出方向，选定后矢量重建 / 归一化做终稿——位图负责探索，不负责终稿的严谨。

## 六、架构

- 两层：内置风格库（每个 = preamble + 锁死 palette + cutout 管线 + thresh + 构造系统）；用户适配层（从项目设计 token 反推 spec / 基于内置风格改 / 纯文字描述）。
- spot vs UI 边界：位图生成图标用于 spot / 卡片头 / 营销位 / 空状态 / 有性格的地方；密集功能 UI（16–24px）用矢量图标库。
- 去背由 agent 根据实际边缘与候选完整性决定，不要求用户选择算法。
