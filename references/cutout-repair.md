# 切图修整

由 agent 对照原稿决定修整和模式，不把算法、容差或候选选择交给用户。保留原始生成图，从原稿重新切图；不要反复处理已经缩放的交付 PNG。自动 QA 只能定位疑点，不能决定灰色究竟是背景还是图案。

## 复核顺序

1. 先读 `qa/summary.md`，再按需读 `qa/report.json` 和单格 `qa/details/NN.json`，逐格比较 `source.png`、`cutout.png`、`cleaned.png`，再检查洋红、浅色和深色底上的最终图。需要判断细小部件时，按报告的 `source_bounds` 从原稿取原尺寸裁切；预览拼图的缩略图不足以验收细节。
2. **外部灰边**：确认是残底后，逐格增大外部去背容差，用能清除残留的最小值。`--background-tolerance N` 是整张图的覆盖值，`--repairs` 可只改有问题的格子。不要把个案使用的 32 当成默认值；过宽会误删与外部相连的灰色主体。
3. **封闭残底**：确认是图案间的空隙后，选该区域内的种子点与尽量紧的矩形，通过 `erase_regions` 清除。它只删除矩形内、与种子四邻域连通且接近实测背景色的像素，不处理同格其他封闭区域。若矩形截断了残留，应调整范围后重新复核，不能直接交付。确认新形成的窄边缘混入背景色时，由 agent 在该区域设置 `refine_edge: true`，并把边缘包含在矩形内；只在矩形内、距清除区域至多 2 像素且有可靠前景参考的部分去混色。未找到可靠参考时保留像素并继续检查，不盲目扩大删除容差。
4. **rembg 误删**：比较模型结果、原稿和色彩候选。`qa/colour-candidate.png` 保留同格布局；rembg 格子的 `qa/colour-candidates/NN.png` 为原裁切尺寸透明候选。确认色彩方案更完整后，用该格的 `mode: "floodfill"` 重新切图，并继续处理残底；不要直接交付尚未归一化的候选。背景不可信时，候选也只是诊断材料，不自动判优。
5. 重新读取报告并复核**所有最终图标**。`candidate_disagreement` 表示两种方法保留的像素不同，不等同于确定的误删。`possible_cutout_loss` 也可能包含外部容差主动去掉的灰边；局部修整掩膜则归入 `repaired_background`，边界低对比差异归入 `edge_ambiguity`。这两类信息提示仍须看图，不以提示数量少作为选图标准。仍无法可靠区分的区域需重新生成，不宣称验收通过。完成检查后按下方格式记录验收结果；无需用户再选择算法、参数或状态。

## 参数与修整文件

| 参数 | 作用 |
| --- | --- |
| `--thresh N` | 边缘前景对比度和 QA 颜色相似度，默认 24；不会提高背景删除容差 |
| `--background-tolerance N` | 与裁切边界连通的背景色差上限，0–255；默认使用采样噪声容差 |
| `--repairs /absolute/task/repairs.json` | 逐格覆盖模式、外部容差，或指定局部背景清除 |
| `--review-file /absolute/task/review.json` | 应用 agent 已完成的视觉验收记录，原有切图参数保持一致 |

色差按 RGB 三个通道的最大绝对差计算。外部容差不改变报告里的背景采样噪声。封闭区域的近乎精确匹配规则会排除与外部连通的采样噪声区域，避免绕过较小的外部容差；设为 0 时不会因“封闭区域”规则删除色差为 1 的外部部件。使用 rembg 的格子，其外部容差只作用于色彩候选。

`repairs.json` 示例（坐标仅用于说明，必须替换为实际裁切坐标）：

```json
{
  "cells": {
    "3": {
      "mode": "floodfill",
      "background_tolerance": 16
    },
    "12": {
      "erase_regions": [
        {
          "seed": [110, 130],
          "bounds": [100, 120, 125, 150],
          "tolerance": 4,
          "refine_edge": true
        }
      ]
    }
  }
}
```

- `cells` 的键是从 1 开始的行优先格号，只能指定本次导出的格子；不要使用前导零。
- 每格三个字段都可省略。`mode` 为 `floodfill` 或 `rembg`，优先于风格模式和自动回退。外部容差优先级为该格覆盖 → 命令行覆盖 → 采样噪声。
- `seed: [x, y]` 和 `bounds: [left, top, right, bottom]` 相对报告 `source_bounds` 对应的**外扩原尺寸裁切**，不是原图全局坐标或 512px 成品坐标。右、下边界不包含；种子和矩形必须位于该格的 `owned_bounds` 内。
- 每个局部区域必须完整指定种子、范围和 0–255 的整数容差；种子须匹配实测背景。模式错误、范围越界、无效种子，以及任意层级的重复 JSON 键（包括重复格号）均在导出前报错，已有输出不变。同一格的修整应合并到一个对象内。
- 局部修整在常规边缘处理之后、清理和缩放之前执行，也用于该格的色彩候选。默认只清除选中区域；可选布尔字段 `refine_edge` 由 agent 在确认混色后启用，局部细化严格限于选区内的 2px 窄边，不改选区外的 RGB 和透明度。rembg 模式保持模型透明度，仅修正有可靠依据的 RGB。
- `applied_repairs` 记录实际删除像素数，启用局部边缘处理时额外记录 `refined_edge_pixels`。0 表示没有对应变更；不能仅凭命令成功就认为问题解决。

```bash
"$SKILL_DIR/.venv/bin/python" "$SKILL_DIR/scripts/slice_icons.py" \
  "/absolute/task/raw/style.png" "/absolute/task/out" \
  --mode floodfill --grid 4 --repairs "/absolute/task/repairs.json"
```

沿用首次切图的 `--grid`、`--count`、`--size` 和风格参数。报告中每格的 `mode` 表示实际使用的方法；全局 `effective_mode: "mixed"` 表示逐格采用不同方法。候选预览含所有导出格，非 rembg 格显示当前清理结果；以本次报告中列出的候选路径为准。


## 验收记录

先逐格检查原尺寸原稿、最终 PNG 和三种底色。`summary.md` 先列验收状态，再列自动检测；`report.json` 每类最多给出 3 个区域示例，完整区域在 `details/NN.json`。检测证据始终保留，正常镂空不会因为验收通过而从记录消失。

Agent 在任务目录写 `review.json`，使用本次报告每格的完整 `fingerprint`（下面是结构示意，不能直接照抄占位值）：

```json
{
  "cells": {
    "9": {
      "fingerprint": "复制该格本次报告的64位指纹",
      "status": "accepted",
      "reviewer": "agent",
      "note": "已对照原尺寸原稿及洋红、白、深色底；星星旁空隙正确，主体和边缘完整。",
      "decisions": {
        "transparent_holes": "valid_hole",
        "edge_ambiguity": "edge_noise",
        "repaired_background": "verified_repair"
      }
    }
  }
}
```

- `status` 写 `accepted` 或 `needs_fix`；`reviewer` 记录实际复核者，`note` 写具体依据。每个格号只写一次。逐类结论适用于该类的所有区域；如果仍有任何区域未解决，该格必须标记 `needs_fix`。
- `decisions` 的键对应报告里的提示代码；值为 `valid_hole`（正常镂空）、`intentional_detail`（图案）、`edge_noise`（可接受的边缘差异）、`verified_repair`（已核实修整）、`false_positive`（其他误报）或 `needs_fix`（仍需返修）。接受前必须处理每个 `review` / `error` 类提示；`info` 仍需随全图检查，可记录对应结论。无报警的格子也要显式验收。
- 沿用原切图命令的全部参数和 `--repairs`，追加 `--review-file /absolute/task/review.json`。脚本重新切图并验证指纹；匹配的验收反映在摘要和预览中，不改变检测结果。缺少分类结论保持 `pending`；空图检查以缩放后的最终 PNG 为准，完全透明的输出始终标记 `needs_fix`，不能用验收记录覆盖。
- 指纹绑定原稿像素、切图参数、背景估计、修整、处理脚本和输出像素。改变任一绑定内容，原记录标为 `stale`，需检查新结果后再记录；不可只替换指纹来跳过复核。每格另存 `output_sha256` 便于核对 PNG 文件。不要在脚本外修改交付图后沿用旧报告。
- 预览：`CHECK` 为尚未视觉验收（无高等级提示），`REVIEW` 为存在待解释提示，`FIX` 为需返修，`STALE` 为旧验收失效，`OK` 为已验收。全部格子均接受时整体才为 `accepted`。省略验收文件不会自动沿用上次通过状态。

切图、预览和报告先在输出目录旁的临时目录完成，成功后再发布编号 PNG 与 `qa/`。处理失败不会改动上次完整结果；发布时先撤下旧 QA，全部 PNG 就位后才发布新报告和预览。发布异常会尝试恢复旧结果，避免新图片沿用旧的 `OK`。

发布前记录事务和文件哈希；若进程被强制终止，重跑会在读取输入前核对现场并恢复上次完整结果，再执行本次切图。恢复途中再次中断也可重跑，已提交的完整批次只清理临时文件。大小写不敏感文件系统中，更换输出路径的大小写拼写也可恢复；脚本会核对输出目录、父目录和事务文件的实际身份，再使用原记录中的临时目录名。清理会逐项核对临时目录、备份及 `backup/discarded/` 隔离文件；若文件被修改或新增、事务记录损坏，脚本停止覆盖并保留现场。清理过程中已删除的条目可在下次重跑时跳过；不要删除旁边的 `.<输出目录名>-transaction.json`、`-backup-*` 和 `-stage-*`，须排查后成功重跑并复核再交付。

旧版完整事务可按整目录哈希恢复；旧版清理到一半且无法核实内容的备份、未记录事务的备份仍需手工处理。恢复不会删除被本次命令用作输入的备份或临时文件，请先把这类输入复制到临时目录外。

同一输出目录从恢复、读取原稿和修整/验收输入，到切图、发布，全程共用一把锁；并发命令会等待。旁边的 `.<输出目录名>.lock` 是可复用的发布锁文件，保留即可。

编辑器不受这把锁约束。脚本会核对开始复制时的 QA 快照；复制或切图期间若有笔记、文件新增、修改或删除，则停止发布，保留当前文件，完成编辑后可重新运行。若变化发生在 QA 刚移入备份时，会保留备份和事务记录供排查，不清理新内容。用户笔记中的文件、目录和失效符号链接按链接保留；`qa/` 根目录、报告、预览、明细与候选的生成路径若是符号链接，会提前报错，不向链接目标写入。

清理只针对旧 `qa/report.json` 明确登记的编号 PNG；有 `output_sha256` 时还须与文件匹配，兼容未记录哈希的旧版报告。原稿和本次修整、验收输入逐跳保护完整符号链接链（含链接目标中的目录链接）及最终文件；若发布或恢复清理会替换、删除其中任何一环，会提前报错。目录归属按实际文件系统身份核对，兼容大小写别名，同时区分大小写敏感文件系统中的不同目录。未登记或已被修改的素材保留；若它们与本次输出重名，脚本在发布前报错，改用新的输出目录即可。报告损坏或文件名无效时停止发布，不按数字文件名猜测归属。交付文件以本次报告列出的路径为准，不直接打包目录中所有 PNG。
